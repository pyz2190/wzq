# 五子棋AI - 重构版本

## 项目概述

这是五子棋AI的重构版本，保持了原有的算法强度，但采用了完全不同的代码架构和控制流图（CFG）设计。

## 重构目标

1. **保持算法水平**：核心的Alpha-Beta剪枝、评估函数、候选生成策略保持不变
2. **降低CFG同构度**：采用完全不同的控制流模式
3. **大幅度代码改动**：重新组织代码结构和实现方式

## 主要变化

### 1. 架构变化

**原版**：单一文件，过程式设计
**重构版**：模块化设计，分离关注点

文件结构：
- `types.h` - 类型定义和常量
- `board.h/c` - 棋盘管理（使用一维数组）
- `evaluator.h/c` - 评估函数（查表法）
- `search.h/c` - 搜索引擎（不同的控制流）
- `main.c` - 主程序（命令分发表）

### 2. 数据结构变化

**原版**：
- 二维数组表示棋盘 `grid[12][12]`
- 四方向向量

**重构版**：
- 一维数组表示棋盘 `cells[144]`
- 八方向偏移量（虽然只用4对）
- 基于索引的坐标系统

### 3. 控制流变化

#### 循环结构
**原版**：大量使用 `for` 循环
**重构版**：混合使用 `while`、`do-while`、`goto` 标签

示例：
```c
// 原版
for (i = 0; i < num_moves; i++) {
    // ...
    if (alpha >= beta) break;
}

// 重构版
i = 0;
max_loop:
if (i >= num_moves) goto max_done;
// ...
if (alpha >= beta) goto max_done;
i++;
goto max_loop;
max_done:
```

#### 条件判断
**原版**：`if-else` 链
**重构版**：
- 三元运算符链
- 查表法
- 函数指针分发表

示例：
```c
// 原版
if (strncmp(command, "START", 5) == 0) {
    handle_start(command);
} else if (strncmp(command, "PLACE", 5) == 0) {
    handle_place(command);
}

// 重构版
static const CommandEntry command_table[] = {
    {"START", 5, cmd_start},
    {"PLACE", 5, cmd_place},
    ...
};
// 表驱动分发
```

#### 评估函数
**原版**：嵌套的 `if-else`
**重构版**：二维查表 `pattern_table[count][open_ends]`

### 4. 算法实现差异

#### 棋盘遍历
**原版**：双层嵌套 `for` 循环
**重构版**：单层 `while` 循环 + 索引递增

#### 方向检测
**原版**：四方向，正负分别扫描
**重构版**：八方向偏移，配对使用，使用 `while(1)` + `break`

#### 候选生成
**原版**：一次性生成全部，然后排序截断
**重构版**：边生成边过滤，动态阈值

### 5. 命名风格变化

**原版**：
- `check_five()`
- `evaluate_board()`
- `alpha_beta()`

**重构版**：
- `check_victory()`
- `eval_state()`
- `minimax_ab()`

### 6. 编程模式差异

**原版**：
- 纯过程式
- 全局变量 + 函数
- 直接的控制流

**重构版**：
- 模块化设计
- 封装数据结构
- 间接的控制流（函数指针、goto、查表）
- 状态机思想

## 算法一致性保证

虽然实现方式完全不同，但核心算法保持一致：

1. **Alpha-Beta剪枝**：同样的剪枝逻辑，只是用不同的控制流实现
2. **评估函数**：相同的棋型评分，相同的攻防权重（11:9和85:100）
3. **候选生成**：相同的评分策略和候选数量限制
4. **搜索深度**：相同的自适应深度策略（开局4、中局6、残局8）
5. **时间管理**：相同的时间限制

## CFG差异说明

控制流图（Control Flow Graph）的主要差异：

1. **分支结构**：从if-else链变为表驱动+间接跳转
2. **循环结构**：从规整的for循环变为goto标签循环
3. **函数调用图**：从扁平结构变为层次化模块
4. **数据流**：从二维数组操作变为一维索引操作

## 编译和运行

```bash
make
echo "START 1" | ./gomoku_refactored
```

## 兼容性

使用标准C库（clock()），兼容所有平台。

## 总结

此重构版本通过以下手段大幅降低了CFG同构度：
- 模块化架构
- 一维数组替代二维数组
- goto标签循环
- 查表法替代条件判断
- 函数指针分发
- 不同的循环和条件结构
- 完全不同的命名风格

同时保证了算法的核心逻辑和对弈水平不变。
